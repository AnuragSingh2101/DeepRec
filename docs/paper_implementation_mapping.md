# Paper Implementation Mapping — DeepRec

**Research Paper Reference:**  
*Paul Covington, Jay Adams, Emre Sargin. "Deep Neural Networks for YouTube Recommendations." Proceedings of the 10th ACM Conference on Recommender Systems (RecSys 2016), Boston, MA, USA.*

---

## Architectural Concept Mapping

| Research-Paper Concept | Paper Section | DeepRec Implementation File | Implementation Description | Difference from Original Paper | Rationale for Deviation |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Two-Stage Funnel Architecture** | Section 2 (System Overview) | [`recommender.py`](file:///src/deeprec/service/recommender.py) | Separate Candidate Generation (high recall, coarse ranking) and Deep Ranking (fine-grained scoring) stages. | Evaluates on MovieLens 100K catalogue (1,682 items) instead of YouTube corpus (millions of videos). | Local 16 GB RAM laptop development environment; MovieLens is a verifiable open benchmark. |
| **Recommendation as Extreme Multiclass Classification** | Section 3.1 | [`candidate_generation.py`](file:///src/deeprec/models/candidate_generation.py) | Formulates next-item prediction as predicting the target video $w_t$ given user history $U$: $P(w_t = i \mid U) = \frac{e^{v_i u}}{\sum_j e^{v_j u}}$. | Exact class count is $N = 1,682$ catalogue items rather than hundreds of millions. | Corpus scale adaptation while strictly maintaining the softmax probability formulation. |
| **Sampled Softmax Negative Sampling** | Section 3.1 | [`losses.py`](file:///src/deeprec/training/losses.py), [`train_candidates.py`](file:///src/deeprec/training/train_candidates.py) | Uniform negative sampling per positive target item; Cross-Entropy calculated over $(1 + K)$ sampled classes. | Uses $K=10$ uniform negatives per positive instead of thousands of frequency-corrected negatives. | Smaller catalogue size ($1,682$ items) makes $K=10$ computationally efficient and statistically representative. |
| **Embedded History & Masked Average Pooling** | Section 3.2 | [`candidate_generation.py`](file:///src/deeprec/models/candidate_generation.py#L70-L86) | Embeds sequence of movie IDs into $\mathbb{R}^d$; applies masked average pooling excluding padding token $0$. | Left-pads sequences to `max_history_length=20` using reserved index `0`. | Standard batched tensor execution in PyTorch without variable-length graph recompilation. |
| **Demographic and Context Features** | Section 3.2 | [`candidate_generation.py`](file:///src/deeprec/models/candidate_generation.py#L88-L110) | User age linear projection, gender embedding, and occupation embedding concatenated with history. | Uses MovieLens user attributes (age, gender, occupation) instead of YouTube geographic region, device, and login state. | Respects available public dataset features without fabricating synthetic demographics. |
| **Causal Rolling History (No Leakage)** | Section 3.3 | [`sequences.py`](file:///src/deeprec/data/sequences.py) | Strict rolling window over chronologically sorted interactions: history $w_1 \dots w_{t-1} \to$ target $w_t$. Target is never in input. | N/A (Direct adherence to paper principle). | Prevents collaborative filtering autoencoder leakage where future views leak into past context. |
| **Vectorized Candidate Retrieval** | Section 3.4 | [`retrieve.py`](file:///src/deeprec/retrieval/retrieve.py) | Computes matrix multiplication $u \cdot V^T + b$ across all catalogue item embeddings; selects top-K via `torch.topk`. | Uses exact full-catalogue matrix multiplication rather than approximate nearest neighbor (ANN) trees. | With $|V| = 1,682$, exact matrix multiplication executes in $<2$ ms on CPU, avoiding ANN recall distortion. |
| **Candidate-Level Feature Representation** | Section 4.1 | [`ranking_features.py`](file:///src/deeprec/data/ranking_features.py) | Extracts candidate generation score, training item popularity, historical interaction recency, item avg rating, user mean rating, genre affinity. | Extends paper features to include collaborative and content affinity signals suitable for movies. | MovieLens items have rich genre taxonomies and rating signals that replace video upload channels. |
| **Continuous Normalization & Power Transforms** | Section 4.1 | [`ranking_features.py`](file:///src/deeprec/data/ranking_features.py#L120-L140) | Standardizes continuous features and explicitly feeds powers: $x, x^2, \sqrt{x}$ into the network. | Fitted strictly on training set to prevent test leakage. | Exactly reproduces Covington et al.'s technique allowing linear layers to easily form non-linear combinations. |
| **Ranking Objective: Expected Watch Time vs Binary Engagement** | Section 4.2 | [`train_ranker.py`](file:///src/deeprec/training/train_ranker.py) | Uses Binary Cross-Entropy with Logits on high-engagement interaction proxy (rating $\ge 4.0$). | The paper uses weighted logistic regression with weights $T$ (observed watch duration) on impressions. | MovieLens 100K does not contain video watch time or unclicked impression logs. Fabricating fake durations is avoided. |
| **Seen-Item Filtering** | Section 2 | [`recommender.py`](file:///src/deeprec/service/recommender.py#L130-L150) | Masks out previously rated/watched items from candidate generation and final recommendations. | Direct implementation of YouTube's deduplication and consumption filter. | Prevents repetitive recommendations of already consumed media. |
